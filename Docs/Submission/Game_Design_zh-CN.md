# CombatSample｜第三人称近战战斗演示

游戏设计说明 · 提交版

## 01 作品概述

CombatSample 是一个以一对一近战交锋为核心的第三人称动作游戏演示。玩家在封闭训练大厅中控制持刀角色，与 AI 敌人交战；通过移动、选择攻击时机和衔接连段削减敌人生命，并观察敌人的攻击节奏与霸体状态。胜利和失败都会进入结算并自动开始下一局。

- 运行平台：Windows x64；单人、本地游玩。
- 开发引擎：Unity 2022.3.62f3，Universal Render Pipeline。
- 唯一游玩场景：CombatTrainingArena。
- 内容规模：一座训练大厅、一名玩家和一名 AI 敌人；不包含选关、多人、成长或存档系统。

## 02 设计目的

### 将注意力集中在战斗本身

以单场景、单敌人的形式减少探索和流程负担，让玩家直接体验接近、出招、命中、受击和重新交战。失败不需要返回菜单，便于快速重复尝试。

### 用动作窗口而不是连续点击决定节奏

攻击由动作配置和衔接窗口驱动。玩家需要观察当前动作阶段选择输入，而不是任何时刻按键都能立即打断动作。地面连段、右键分支、挑空与空中追击构成不同的进攻路径。

### 让战斗状态能够被看见

生命条表示双方剩余资源，命中特效、音效、短暂停顿和镜头反馈强调接触瞬间；敌人拥有霸体标签时的金色轮廓帮助玩家识别其不易被打断的状态。霸体不等于无敌，伤害与受击反应分别处理。

## 03 核心循环

进入训练场 → 调整距离与视角 → 选择出招和连段 → 观察伤害与敌人反击 → 胜负结算 → 自动重新开始。

玩家生命降为零时失败；指定敌人生命降为零且玩家存活时胜利。同一帧双方死亡时按玩家失败处理。两种结果都使用场景中保存的 5 秒结算倒计时，随后黑底显示“正在重新开始…”并等待 2 秒，之后才实际重新加载场景。两段等待均使用真实时间。


## 04 主要功能与体验

| 模块 | 当前演示内容 | 设计作用 |
| --- | --- | --- |
| 移动与镜头 | 相机相关方向移动、鼠标视角、目标软锁切换 | 在接近、绕行和攻击时保留方向控制 |
| 动作与连段 | 地面轻击连段、按窗口输入的右键分支、挑空与空中连段 | 提供动作选择与衔接时机，而非只反复播放单次攻击 |
| 命中与受击 | 攻击有效窗口、伤害、生命、不同受击反应 | 将动画表现与实际攻击结算对应起来 |
| 状态与反馈 | 霸体标签、金色轮廓、命中特效、音效和速度／镜头反馈 | 帮助判断攻击是否命中以及敌人当前状态 |
| 敌人 AI | 行为图驱动接近、移动和攻击选择，配置不同动作及冷却 | 形成可观察、可反复练习的交战过程 |
| 完整流程 | 玩家／敌人血条、胜负提示、倒计时、转黑、自动重开 | 形成无需重启程序的重复游玩闭环 |

## 05 键鼠操作

| 输入 | 作用 |
| --- | --- |
| W / A / S / D，或方向键 | 移动角色 |
| 移动鼠标 | 控制观察方向 |
| 鼠标左键 | 轻击输入；根据当前动作窗口衔接连段 |
| 鼠标右键 | 重击／派生输入；响应取决于当前动作与地面／空中状态 |
| 鼠标中键 | 切换目标软锁；距离等条件不满足时可能无法保持 |
| Esc | 释放鼠标；不是暂停菜单 |
| 鼠标左键（释放鼠标后） | 重新锁定鼠标，并可能同时产生攻击输入 |
| Alt + F4，或窗口关闭按钮 | 关闭游戏 |

推荐以键鼠体验战斗。不同动作有各自的衔接窗口：按下右键并不保证在任意时刻触发相同动作，地面与空中状态也会影响后续分支。

建议首次体验先用左键观察地面连段，再在不同动作阶段尝试右键分支；出现挑空后继续轻击体验空中衔接。空中连段受本轮滞空内的起手次数限制。


## 06 场景与呈现

训练场采用封闭的工业实验大厅：灰色地面、网格与距离标记、模块墙面、顶部照明以及少量橙色引导。空间服务于单场战斗，不以探索为目标；清晰的地面参照便于判断位移和交战距离。

结算采用克制的中央排版：失败为灰白标题与暗红细线，胜利为暖白标题与低饱和金色细线。独立数字与连续缩短的进度线表示结算剩余时间；转黑后的两秒是明确的演出等待，不伪造加载进度。

## 07 工程实现与制作范围

本项目的玩法组织与集成主要位于 Assets/Scripts 和 Assets/Data，包括：角色运动与固定步仿真、输入缓冲、数据驱动动作与取消窗口、命中及状态结算、AI 任务适配、镜头协调、HUD 与胜负重开。工程同时保留动作时间轴、动画／Root Motion 烘焙及检查工具，便于查看与调整配置。

工程使用第三方角色、动画、音效／特效和插件，不将这些内容表述为全部从零制作。Animancer、Kinematic Character Controller、NodeCanvas、Cinemachine 等提供底层或工具能力，具体玩法与数据配置在其上进行组织和集成。目录及许可说明另见随附的《素材与第三方说明》。

提交范围以最终场景和随附工程为准。第三方插件、素材及可复用的工程基础，与本项目的具体玩法配置和集成工作分别说明；素材归属及使用范围遵循原有许可。

## 08 工程查看与运行

- 使用 Unity Hub，以 Unity 2022.3.62f3 打开解压后的 CombatSample 工程目录。
- 等待 Package 恢复、脚本编译与资源导入完成，然后打开 Assets/Scenes/CombatTrainingArena.unity。
- Build Settings 仅启用该场景；胜负重开仍加载同一场景。
- 重点源码：Assets/Scripts/Action、Actor、Combat、Graph、Camera、UI；玩法数据：Assets/Data。
- 游戏端应运行整个 Windows 构建目录中的可执行程序，不能单独移动 exe 而丢弃 Data 目录及 DLL。

源工程保留完整资源与制作数据，未为压缩体量删除其他开发场景或素材。缓存、IDE 生成文件和 Git 历史不属于提交工程必需内容。首次导入所需网络、依赖恢复和最终验收边界详见《运行与工程打开说明》。
