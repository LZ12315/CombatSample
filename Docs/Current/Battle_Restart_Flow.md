# 胜负结算与整场重开

状态：死亡重开与初版提示已由用户试玩确认可用；本轮接入胜利结果，共用现有倒计时与重开过渡。新版胜利画面与场景接入尚未完成 Play Mode／Player 验收。不修改场景、Prefab 或 Build Settings，不增加角色动画、按钮或全局暂停。

默认流程：**3 秒胜负结算倒计时 →「正在重新开始…」演出等待 2 秒 → 才真正加载整个战斗场景**。Inspector 已保存的时长优先于代码默认值。

## 胜负判定

- 当前按**一对一**处理，不是清空所有敌人或波次的通用关卡系统。
- `BattleFlowController` 显式绑定玩家 `Player Combater`，以及决定本局胜利的敌人 `Enemy Combater`。
- 玩家死亡为失败；指定敌人死亡且玩家存活为胜利。无须检查致命一击来自谁。禁用／销毁敌人、切换锁定目标均不等于胜利。
- 敌人未指定时，只在绑定时查找同场景的其他活动 `ActorCombater`。恰好一个时自动绑定，并保留这个运行时引用，之后不跟随锁定目标变化。没有候选或候选不唯一时给出警告，不猜测敌人；玩家死亡仍正常结算，但胜利功能需要手动指定敌人。此回退没有阵营识别；有多个角色时应显式配置。
- 使用现有 `ActorCombater.Died` 事件，不更改伤害或死亡禁用时序。HealthChanged / Died 逐订阅者捕获并记录异常，错误的 UI／表现回调不应阻断后续死亡通知或角色禁用。致命归属在扣血时锁定；血量观察者追加的另一发致命伤害不会让原非致命命中重复发死亡通知。
- 结算回调只标记待判定，统一在 `LateUpdate`、本渲染帧固定 Tick 命中批次结束后确定结果。**同一帧双方死亡时失败优先**，不依赖死亡回调先后顺序。
- 结果确定后锁定本局结算，只启动一条重开流程，后续死亡不会叠加协程或更改结果。首次绑定放在 `Start`，避免将尚未 `Awake` 的零血量误判为死亡。禁用组件会取消订阅、停止等待并隐藏 UI；重新启用时重新读取双方死亡状态，从头开始结算。

## 显示与计时

- `Assets/Scripts/UI/BattleResultView.cs` 由原 `BattleDeathView.cs` 扩展并改名，保留脚本 `.meta` GUID。胜负共用同一个自动生成的 Screen Space Overlay Canvas，排序 200，在默认血条 HUD 之上，无须另建或绑定 UI。
- 失败：「玩家已死亡 / DEFEATED」，灰白标题与暗红细线。
- 胜利：「战斗胜利 / VICTORY」，暖白标题与低饱和金色细线。
- 共用轻微上移淡入、背景渐暗、固定「重新开始」标签、独立 `03 → 02 → 01` 数字及连续缩短的进度线，不显示 `00`。
- `Time.realtimeSinceStartupAsDouble` 同时驱动数字、进度线与动画。结算倒计时结束后才开始完整的第二段等待；慢帧不会吃掉这两秒。慢动作或 `Time.timeScale = 0` 不影响两段等待和 UI 动画。
- 重开过渡收起结算标题、数字与进度线，背景转黑，仅保留小号「正在重新开始…」。**这两秒不调用加载 API、不后台预加载，也不显示虚假加载百分比。** 进度线只代表结算倒计时，不代表加载。
- 两段等待结束后恢复 `Time.timeScale = 1f`，按组件所在场景完整路径调用 `LoadSceneAsync(..., LoadSceneMode.Single)`，保持黑底提示直到旧场景卸载。默认约五秒后发起加载，帧调度可能略有延后；实际加载耗时另计。
- 正常游玩无结算遮罩，重载后 UI 随旧场景销毁。没有 GraphicRaycaster，文字／遮罩不接收射线，不修改输入或光标。等待期间不额外暂停世界或禁止玩家操作。
- 未保存或未加入启用构建列表的场景，等待结束后显示「无法重新开始，请检查场景配置」并记录错误，不尝试加载其他场景。

## Unity 接入

1. 停止 Play Mode，打开实际战斗场景。在场景根级创建 `BattleFlow`，挂载 **Combat > Battle Flow Controller**；已有组件可直接复用，每场景只保留一个。
2. 指定玩家的 `ActorCombater`；建议同时显式指定决定胜利的敌人 `ActorCombater`。两者不能是同一角色，必须与流程组件处于同一场景。流程组件不能放在任一角色物体或其子物体上，避免角色死亡禁用后中断结算；代码会拒绝这类配置。
3. `Restart Delay Seconds` 为胜负结算倒计时，默认 **3**；`Restart Transition Seconds` 为「正在重新开始…」的演出等待，默认 **2**。胜利和失败使用相同配置。
4. 保存场景，在 **Build Settings > Scenes In Build** 中加入并勾选这个场景。代码使用完整路径，不依赖 Build Index 或同名匹配。

**现有 Inspector 覆盖优先。** 前次只读核对发现 `HyperGraph.unity` 中 `restartDelaySeconds` 为 **5**，没有自动改写；若仍保持该值，胜负均为 **5＋2 秒**。需要 **3＋2 秒**时请在 Inspector 改回 3。迁入新场景时要重新确认双方引用。

本方案用于完整单场景战斗：`Single` 加载会卸载其他普通场景，不保留 Additive 启动场景。静态字段、常驻对象及运行时修改的 ScriptableObject 不会自动复原。输入控制器的 Debug 开关若启用，重载后仍可能按其配置重新开启慢动作。

## 字体与分发

`Assets/Resources/UI/BattleDeathFont.otf` 保持现有资源路径，是 Noto Sans SC Regular 的改名子集，现扩展为胜负中英文提示与数字所需的 **50 个字符**，约 **12 KiB**。`Resources.Load<Font>` 读取，Importer 保留 `Include Font Data`，不依赖接收机器安装中文字体。子集只用于本界面，修改文案须先补齐字形。

源字体版本、SHA-256 与完整 OFL 1.1 许可证见同目录 `BattleDeathFont-License.txt`。工程／游戏分发需保留说明，可复制许可证到游戏输出目录。字体处理工具位于系统临时目录，没有新增 Python 或 Unity Package 运行依赖。

人工验证：

2. 指定敌人死亡：显示金色胜利界面，倒计时后转黑，提示完整等待两秒后才加载；重载后双方恢复。
