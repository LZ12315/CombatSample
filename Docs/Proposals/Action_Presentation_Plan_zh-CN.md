# Action 表现制作计划：特效、曲线震屏与预览

## 状态与执行约束

**目标已确认；阶段 0 已完成核对，当前停在阶段 0 交付点，阶段 1 尚未开始。**

核对结果、验收样本和下一阶段有限范围见[阶段 0 记录](Action_Presentation_Stage0_Review_zh-CN.md)。本轮未修改功能代码或资产，也未重跑 Unity 验证。

此前工作区已经存在部分候选实现，不从零重写，也不因为已经写了就必须保留。后续先核对现有实现与本计划的差距，再决定保留、修正或删除。既有测试结果只作为证据，不代替制作流程和实际画面验收。

- 每次只推进一个阶段，阶段结束后交付结果、问题和下一步建议，**不自动进入下一阶段**。
- 若发现需要改变已确认行为、扩大相机配置范围或增加新系统，先说明原因再确认，不自行扩展。
- 修改保持小而可审查，保护工作区其他任务的修改。不顺带整理无关代码、资产或架构。
- 不批量迁移 Action、Scene、Prefab；必要的兼容或资源改动单独列明。

## 一、最终目标

让动作制作者在 Action 时间轴上，方便地配置：

1. **某段动作期间的特效。**
2. **某段动作期间的震屏。**
3. **足够完成制作的参数编辑、诊断与隔离预览。**

质量要求是：看得懂、调得动、实际播放可靠。不是以类的数量、字段的数量或测试通过数作为完成标准。

## 二、范围与行为合同

### A. EffectItem：动作区间特效

| 制作问题 | 本次交付 |
| --- | --- |
| 播什么 | 指定特效 Prefab，每次进入区间创建一次 |
| 在哪里 | Actor 根、Humanoid 骨骼、明确的相对 Transform 路径，加位置偏移 |
| 怎么移动 | 留在生成位置，或跟随挂点位置 / 缩放 |
| 朝哪里 | 挂点相对、世界方向、屏幕方向；明确生成时计算还是持续更新 |
| 怎么播放 | 缩放、显式粒子速度、遮挡、固定 / 随机屏幕角及 Roll 等现有 Damage VFX 的适用能力 |
| 何时结束 | 区间结束、动作打断、Abort、角色禁用等生命周期边界立即清理 |

边界：

- 位置绑定与朝向策略分开，不让父级关系暗中改变用户选定的朝向语义。
- 随机角每次进入采样一次，不随连续朝向更新重新抽样。
- 缺失挂点或必要相机应说明原因并跳过，不静默回退。
- 共用确实相同的初始化 / 朝向能力，但不把 Damage 的命中参与者、锚点或独立 Lifetime 搬进 Action。
- 粒子有显式模拟速度，不自动让任意粒子、Trail、Animator、脚本跟随 Action 时钟。
- 不改变 Damage / 弹反反馈既有上下文、位置和寿命语义。

### B. ScreenShakeItem：动作区间曲线震屏

| 制作问题 | 本次交付 |
| --- | --- |
| 往哪里震 | 简单方向：上下、左右、前后、自定义向量 |
| 如何运动 | 可编辑的有正负运动曲线，不只是固定正弦的强度包络 |
| 更细的控制 | 可选各位置轴曲线与旋转曲线；简单 / 分轴模式互为替代 |
| 多大、多远 | 位置与角度幅度使用明确、不同的单位；可配置作用距离 |
| 如何随动作变化 | 曲线横轴为 Action 归一化进度，慢速跟随，暂停保持当前值 |
| 何时结束 | 退出立即停止自身事件，不影响其他 Action 或命中 / 弹反震屏 |

边界：

- 使用原生 Cinemachine Impulse；它是实现手段，验收目标仍是方向正确、曲线可控、混合正常、停止干净。
- 一次进入对应一个区间拥有的事件；不逐帧重发，不清空全局 ImpulseManager。
- 使用专用 Action 接收策略，不随意修改共享命中 Listener。
- 默认 camera space 按接收虚拟相机解释，再交给 Cinemachine 混合，不承诺最终混合相机轴上的后处理语义。
- 没有延迟传播、secondary reaction 或自动尾震；暂停时允许保持非零偏移。
- 默认曲线首尾归零；用户曲线端点非零只警告，不自动改写。
- 旧原型强度和频率不承诺等价手感，代表动作需要重新调参。

### C. 制作界面、诊断与 Preview

- 时间轴继续使用 Range 编辑方式；Details 分组清楚，只显示当前模式有关的参数。
- 参数明确标注单位、参考空间和更新策略。
- Prefab / 挂点 / 必要配置缺失，非法曲线或方向、非零端点、极短区间等提供可操作的诊断。
- 常见 ParticleSystem 特效可以在隔离 Preview 中查看位置、朝向与大致播放效果，支持前后拖动和清理。
- 屏幕朝向使用预览相机；不发真实 Impulse，不污染场景或运行游戏逻辑。
- 不支持的脚本型 Prefab 必须明确说明，而不是实例化后声称确定性回放。
- 预览粒子年龄、当前发射器姿态与运行时历史存在的差异必须说明；不要求重演整段世界空间发射轨迹。
- 可提供位置 / 朝向辅助线和震屏信号方向提示；不要求震屏驱动预览相机。

### 共同生命周期

- 两种 Item 都使用 `[Start, End)` 区间所有权；沿用现有调度阶段和最后有效帧的退出规则，不重排 Action / World / Hit / Finish。
- 待创建资源被取消后不得补生成；已创建资源立即停止 / 隐藏，再释放。
- 多个区间独立清理，循环重新进入才重新创建。
- 没有粒子尾迹、隐藏最短显示帧或自动延长。短区间可能在两次渲染之间完成，需明确警告。
- 已提交 Hit 的有效性、Combat 裁决和 Actor 整角色协调职责保持不变。

## 三、明确不做

- Actor / Combat / Targeting 的架构重构。
- 万能特效编排系统、资源池体系或任意 Prefab 确定性回放。
- 任意脚本、Animator、Trail 与 Action 时钟的自动同步。
- 自动尾迹、额外尾震、隐藏的最短显示时间。
- 为了抽象完整而引入额外层级、模块或配置。
- 大规模相机、场景、Prefab、美术资源调整。
- 把完整集成测试负担加入默认 Test Runner。

## 四、阶段计划与交付停点

### 阶段 0：核对差距，确定验收样本

**先不增加功能。**

工作：

1. 阅读当前候选实现，按上面的三类目标标注“已有且有证据 / 已有但未验收 / 缺失 / 超出范围”。
2. 列出会涉及的具体文件和必要相机接入点，区分本任务改动与其他工作区修改。
3. 从现有资源中选出代表动作 / 特效 / 相机路径；若无合适资源，列明最小验证夹具，而不是扩展美术制作。
4. 核对关键参数语义与旧数据兼容，重点包括曲线归一化、朝向更新、Prefab 缩放与预览限制。

交付：一份简短差距表、样本清单和下一阶段的有限修改范围。

**停止条件：目标可以映射到具体行为和样本。需要新增决策时先确认，不边实现边改变目标。**

### 阶段 1：收口 ScreenShakeItem

工作：

1. 保留已可用的原生事件 / Listener 实现，只修正阶段 0 找到的差距。
2. 收口简单方向 / 分轴曲线、可选旋转、幅度与距离参数；移除被替代的手动相机偏移路径。
3. 验证 Action 连续进度、慢速 / 暂停、严格取消、独立叠加和专用接收策略。
4. 用代表相机验证 FreeLook、软 / 硬锁与过渡；记录仍需人工观察的画面问题。

交付：可单独评审的震屏改动、验证证据和残余问题。

**通过标准：制作者能调出一段有正负运动的震屏，方向与曲线一致；结束无自身残留，不取消命中震屏。无法实看画面则标为未验收，不以测试替代。完成后停。**

### 阶段 2：收口 EffectItem

工作：

1. 收口 Prefab、挂点、留置 / 跟随、朝向与更新策略。
2. 核对 Damage 适用能力的共享，避免改坏其原有外观和寿命。
3. 验证实际实例的创建、更新与立即隐藏 / 销毁，而不只检查 Dispose 调用次数。
4. 用代表特效检查缩放、粒子速度、遮挡、随机角和挂点运动。

交付：可单独评审的 VFX 改动、配置示例和生命周期结果。

**通过标准：武器跟随特效，以及留置 / 屏幕朝向特效能按配置工作；打断和禁用立即清理，Damage / 弹反无已知回归。完成后停。**

### 阶段 3：收口制作流程与隔离 Preview

工作：

1. 按实际制作顺序调整 Details，避免无关参数和隐式组合。
2. 完善必要诊断，不做泛化的诊断框架。
3. 验证隔离粒子预览的资源检查、姿态求值、时间拖动、视角变化与清理。
4. 实际操作拖边、修改、复制、静音、Undo / Redo 和保存重载，检查引用与旧数据兼容。

交付：能走通的编辑器操作步骤、明确的预览支持范围与已知限制。

**通过标准：制作者不翻代码也能配置代表样本，并知道没效果时该检查什么；预览不污染真实场景。完成后停。**

### 阶段 4：代表动作验收与清理交付

工作：

1. 按下方矩阵串联验收，优先真实制作 / 播放，不继续增加功能。
2. 删除已被替代且无需兼容的路径，检查数据迁移与文档一致性。
3. 汇总文件、自动验证、人工验证和仍未通过 / 未执行的事项。

交付：最终交付记录。未执行的视觉验收必须保持未完成状态，不宣布整体完成。

## 五、代表验收矩阵

| 样本 / 操作 | 可观察结果 |
| --- | --- |
| 武器挂点持续特效，角色移动 / 转身 | 跟随位置及指定朝向正确，缩放符合配置 |
| 世界留置特效，角色随后离开 | 保留生成位置，不随角色漂移；区间结束仍清理 |
| 屏幕朝向特效，切换初始 / 连续更新策略 | 朝向更新符合所选语义；预览用预览相机 |
| 简单方向曲线跨正负值 | 画面运动与曲线方向一致，不存在隐藏正弦 |
| 分轴位置 / 旋转曲线 | 各轴和单位清楚，模式不暗中叠加 |
| Action 暂停、慢速、恢复 | 震屏采样按合同保持 / 推进；粒子保持显式独立速度语义 |
| FreeLook ↔ 软 / 硬锁，含混合 | 原生接收和混合正常，无重复应用或累积漂移 |
| 两份 Action 震屏 + 命中 / 弹反 Impulse | 停止其中一份不会取消其他事件 |
| 正常结束、打断、Abort、Disable、销毁 | 无补生成，无自身残留，无隐藏尾迹 |
| 极短区间与非零曲线端点 | 有诊断，不擅自延长或修正数据 |
| Preview 前后拖动、换配置、关闭、进 Play Mode | 隔离实例正确重采样 / 释放，不执行游戏逻辑 |
| Undo / Redo、复制、保存重载、旧原型数据 | 内容与引用保留，兼容语义明确 |

## 六、验证策略与进度汇报

- 默认 EditMode：只保留稳定数据 / 生命周期 / 采样合同的少量确定性测试。
- 编译：针对实际修改过的源码检查；不把编译已保证的结构再写成测试。
- 原生集成：仅覆盖纯测试不能证明的 Impulse 接收 / 取消、实际对象生命周期、隔离预览等；可放在单独验证入口，不拖累默认套件。
- 视觉与操作：相机混合手感、遮挡 / 材质、实际 Preview 画面和编辑器交互必须单独记录人工结果。
- 修改某一部分先跑相关验证；综合回归放在阶段收口，避免每改一点就反复启动完整 Unity 流程。
- 验证失败先区分生产问题、夹具问题与环境限制；不因测试夹具失败扩大功能范围。
- 每阶段汇报：做了什么、哪些文件、验证了什么、尚未验证什么、是否需要新决定。不得只报测试通过数。

## 七、完成定义

只有同时满足以下条件，才算本次目标完成：

1. 三个交付面均能支撑代表动作的实际制作和播放。
2. 生命周期、原生相机集成与现有命中 / 弹反反馈没有已知阻断问题。
3. 编辑器的保存、调整、诊断和支持范围内的预览可用。
4. 验收矩阵有明确结果，未执行项没有被包装成通过。
5. 文档描述实际实现与限制，未保留互相矛盾的旧原型说明。

现行实现说明见 [Action 表现合同](../Current/Action_Effect_Contract.md)。本计划约束后续工作范围，不代表现行实现已经通过全部验收。
