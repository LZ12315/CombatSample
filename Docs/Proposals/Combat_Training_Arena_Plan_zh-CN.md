状态：用户已确认并开始实施。独立场景与视觉首版已生成；中央自由/软锁/硬锁短测已执行，墙边镜头验证失败，阶段 C 尚未收口。当前成果、截图与验证边界见[训练大厅首版记录](../Current/Combat_Training_Arena.md)。

## 1. 已确认目标

- 参考《街霸 6》训练场的灰色网格、极简感与科技实验室气质，做原创场地，不复制其素材。
- 封闭式训练大厅，服务现有 Demo 的战斗展示与日常试招。
- 沿用现有角色、战斗系统、输入、HUD 和镜头逻辑，不借场景制作重写系统。
- 优先级：战斗可读性 > 镜头适配 > 空间美感 > 装饰细节。

## 2. 仓库依据与实施边界

- 当前 README 指定 `Assets/Scenes/HyperGraph.unity` 为主工作场景；以其当前已保存状态作为接入候选，不以旧测试场景代替现行 Demo。
- 项目包含 URP 14.0.12、Cinemachine 2.10.7；具体 Renderer 能力、后处理开关及相机碰撞配置在实施第一阶段核对，不默认已有防穿墙能力。
- 当前镜头有 FreeLook、SoftLock、HardLock，场地必须检查自由旋转、锁定绕行和切换构图。
- 工作区已有大量未提交改动，包含 HyperGraph、角色、动作与镜头。不得覆盖、还原或顺带整理；开始制作前确认 Unity 中未保存内容，取得已保存基线。
- 默认新建 `Assets/Scenes/CombatTrainingArena.unity`，从确认后的工作场景副本接入，保留原场景与游戏对象引用。不自动切换 Build Settings 入口。
- 如需改动共享渲染资源、相机行为或碰撞层配置，单独提出原因与影响，再决定；不悄悄纳入美术制作。

## 3. 视觉方案：中性冷灰训练大厅

### 总体印象

空间有真实结构，但背景克制。中灰哑光地面、浅灰网格墙、深灰结构框架，少量冷白灯光与橙色识别标记。科技感来自精确分区、刻度、面板接缝与建筑灯光，不依赖满屏霓虹或大量屏幕。

从正常战斗机位看，先看到角色与攻击，再看到网格、中心标记和大厅边界。避免做成纯白无影棚、黑暗仓库或杂物密集的科幻走廊。

### 地面

- 连续平整的主战斗面，不做台阶、坑洞或中央障碍。
- 初始以 1 m 细网格、5 m 主网格建立尺度；线宽与对比度按游戏镜头调整，避免远处闪烁与摩尔纹。
- 中心十字、主轴线、边缘刻度和简洁区域编号；中心不放巨大抢眼 Logo。
- 哑光复合面板或细腻混凝土质感，仅少量磨损；不做镜面地板。
- 网格与标线尽量用材质实现，不逐格堆物体；装饰线不承担碰撞。

### 墙面与天花

- 四面围合，墙面延续网格语言；深色底座、面板主体、上部结构分层。
- 墙角采用斜切或内收装饰处理，减少视觉死角；碰撞仍保持简单连续。
- 一面主识别墙：`COMBAT LAB / SECTOR 01` 一类原创标识，另设一处封闭检修门作为尺度参照，不制作开门系统。
- 高挑天花与少量嵌入式灯槽形成完整室内空间，不用密集低垂管线压迫镜头。
- 灯带只强调结构和方向，不在每条网格上发光。

### 灯光与色彩

- 中性偏冷的宽柔主光，辅以适度填充，使角色转向任何方向都能辨认轮廓与武器。
- 橙色只用于警戒线、编号与关键节点；冷白用于照明，避免橙青双色铺满场景。
- 控制地面与角色脚底的接触阴影，让人物站得住。
- 克制 Bloom 和色调映射；首版不使用景深、强雾或额外运动模糊遮挡战斗信息。
- 少量有贡献的实际灯光，装饰灯槽以发光材质为主；发光材质不等同于已经照亮环境。

## 4. 空间初始尺度（灰盒验证后再定）

| 项目 | 初始建议 | 目的 |
| --- | --- | --- |
| 大厅内净尺寸 | 约 36 m × 36 m | 容纳 3D 追击、绕行和镜头回转 |
| 中央视觉战斗区 | 约 24 m × 24 m | 聚焦展示，不设置内圈隐形墙 |
| 外围可行走缓冲 | 每侧约 6 m | 让常态交战远离墙体；并非防穿墙保证 |
| 室内净高 | 约 12 m | 兼顾仰视、空中动作与较大角色 |
| 初始双方距离 | 约 6–8 m | 仅作候选，按现有索敌和开战方式验证 |

尺寸不是最终承诺。第一阶段先测当前角色尺度、攻击位移、跳跃高度及镜头最大后退距离，再调整大厅。保留世界尺度，不通过缩放角色或改镜头手感硬凑空间。

平面关系：实体外墙 → 可行走缓冲区域 → 地面标线定义的中央战斗区域。只有大厅实体边界阻挡角色，不增加空气墙式的中央擂台。

## 5. 分阶段实施

### 阶段 A：接入核对与灰盒

1. 确认当前已保存工作场景，记录角色、敌人、相机、HUD、光照和后处理配置；记录原场景实际游戏画面与性能基线。
2. 核对角色碰撞层、镜头遮挡处理、是否使用 NavMesh 等环境依赖，不预设已有导航或防穿墙。
3. 新建场景副本，保留玩法对象及场景内引用，仅替换环境；不要同时留下两套地面碰撞或重复灯光。
4. 搭建地面、四墙、天花、基本照明与出生位置，先验证空间。
5. 在中心、墙边、角落验证移动、战斗、锁定与镜头；墙边问题优先通过空间结构处理。如果仍需相机防遮挡改动，作为单独待确认项，不伪装成场景参数调整。

**阶段出口：** 新场景可以直接进入现有战斗；碰撞与镜头问题已验证或明确记录，再进入美术细化。

### 阶段 B：视觉首版

1. 完成网格地面、墙面分层、深色框架与天花灯槽。
2. 建立少量可复用材质，调好粗糙度、网格密度、接缝和标线。
3. 添加主识别墙、检修门、区域编号与少量警戒色。
4. 用实际游戏机位调光照、阴影与后处理，不只看 Scene 视图。
5. 提供三类截图：正常战斗机位、反向/墙边机位、全景结构视图；条件允许时录制短段战斗视频。

**阶段出口：** 用户确认空间、配色和完成度方向；先看画面再追加细节，避免一次性堆满资产。

### 阶段 C：战斗适配与收尾

1. 测试现有角色组合，尤其是实际接入的大体型敌人、击退、空中动作和高亮特效。
2. 调整标线对比、墙体明度和灯光，使敌人预警、武器轨迹与 HUD 保持清楚。
3. 检查墙边镜头、角落碰撞、远处网格闪烁、阴影漏光和材质缺失。
4. 整理环境 Prefab、材质与必要的制作工具，检查新增 GUID 和引用。
5. 在相同硬件、分辨率、画质和战斗条件下对比 CPU/GPU 帧耗时、Draw Calls 与阴影开销；先定位新增热点，不承诺未经测量的帧率。
6. 记录场景打开方式、主要可调参数、验证结果与剩余问题。是否替换正式演示入口另行决定。

**阶段出口：** 可直接打开试玩的新场景、可复用环境资产、视觉对照和人工验收记录。

## 6. 资产与技术方案

拟新增路径（按实际需要创建，不预建空目录）：

- `Assets/Scenes/CombatTrainingArena.unity`
- `Assets/Prefabs/Environment/CombatTrainingArena/`
- `Assets/Art/Material/CombatTrainingArena/`
- `Assets/Art/Models/CombatTrainingArena/`
- `Assets/Art/Textures/CombatTrainingArena/`
- `Assets/Art/Shaders/CombatTrainingArena/`：只有现有材质不足以稳定呈现网格时添加。
- `Assets/Scripts/Environment/Editor/`：只有重复搭建确有需要时添加小型编辑器工具，不建立通用关卡生成框架。

实现原则：

- 首版以自制基础几何和材质完成，不依赖购买美术包或新增插件。
- 优先现有 URP 材质；如需程序化网格，使用适配当前 URP 的抗锯齿、远距离衰减方案。
- 场景资产在编辑期落盘，可直接选择和修改；不让运行时临时生成承担正式场景制作。
- 环境按地面、墙体、天花、灯光、标识分组，玩法对象保持独立。
- 使用简单碰撞体；不让细小接缝、门把手或装饰边条影响移动。
- 优先场景专属材质与后处理配置，不修改全项目共享配置来得到局部效果。
- Unity 资产通过编辑器流程创建并保留对应 `.meta`，避免手写大段场景 YAML 或重建已有 GUID。

## 7. 验收清单

### 视觉（人工）

- [ ] 正常战斗机位能明确感受到封闭训练设施，而不是默认灰盒。
- [ ] 灰色网格、极简构图、科技实验室气质三者统一。
- [ ] 角色、武器、敌人预警和命中特效比环境更醒目。
- [ ] 四个方向都有基本完成度，不只一面墙可截图。
- [ ] 运动中网格无明显闪烁，灯光不过曝，地面不靠强反射抢镜。

### 玩法与镜头（人工）

- [ ] 现有移动、攻击、闪避、锁定、AI、命中反馈和 HUD 没有因环境接入退化。
- [ ] 中心、墙边、角落分别测试；连续击退和移动不穿地、不被接缝绊住。
- [ ] FreeLook 绕场旋转、SoftLock 绕敌、HardLock 及模式切换均按当前可用入口验证；不可用入口记录限制，不新造输入系统。
- [ ] 空中动作、震屏和较大敌人的构图没有明显天花或墙体遮挡。
- [ ] Play/Stop 后无新出现的 Missing 引用、重复相机/监听器或 Console 错误。

### 工程与性能

- [ ] 新场景可独立打开进入战斗，原工作场景不被覆盖。
- [ ] 本次修改只包含计划内环境资产及必要接入；不混入现有未提交改动。
- [ ] 若新增代码，执行相应编译和有意义的合同测试；不为场景对象名、网格尺寸或截图构图增加脆弱自动测试。
- [ ] 记录 Unity 实测结果与同条件性能对比；静态检查不冒充 Play Mode 或 Player Build 验收。
